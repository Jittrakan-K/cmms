# CMMS

ระบบบริหารงานซ่อมบำรุง เว็บ HTML5 ล้วน ไม่ต้อง build

เปิดครั้งแรกจะใช้ข้อมูลตัวอย่าง (ไลน์ SMT 2 ไลน์) ที่เก็บในเบราว์เซอร์เครื่องนั้น จนกว่าจะเชื่อม Firebase

## หน้าในระบบ

| แผ่นงาน | หน้าที่ |
| --- | --- |
| SH-09 แดชบอร์ดและภาพรวม | รวมหน้าแดชบอร์ดกับภาพรวมเดิมเป็นหน้าเดียว เลื่อนลงอ่านได้ (จัดเป็นหน้าเฉพาะโหมดจอทีวี) ด้านบนเป็นตัวเลขสรุป 5 ช่อง ตามด้วยแผ่นข้อมูลที่แบ่งช่องด้วยเส้นบาง: ใบแจ้งซ่อมรายเดือนปีนี้เทียบปีก่อน (ยอดตั้งแต่ต้นปีและเปอร์เซ็นต์เทียบช่วงเดียวกันปีก่อน) + สถานะใบงาน / เวลาหยุดเครื่องและครั้งที่ขัดข้อง 7/30/90 วัน + ความพร้อมเครื่อง 7 วัน (Availability เวลาหยุดรวม เครื่องหยุดนานที่สุด PM ทันกำหนด MTBF/MTTR) / สุขภาพเครื่องจักร + PM ที่จะถึง + คลังอะไหล่ / ใบงานที่เปิดอยู่ 8 ใบ (งานจริงก่อนใบย้อนหลัง เรียงตามความสำคัญและแจ้งล่าสุด) ถัดลงไปเป็นทีมช่าง เครื่องมือวัด หมวดเครื่อง แผนผังเครื่องจักร (เปิดมาแสดงแผนผังที่มีจุดเครื่องมากที่สุดทันที เช่น Fac A) สถานะเครื่อง 7 วัน และใบงานล่าสุด ลิงก์เดิม `#overview` จะเปิดหน้านี้ |
| SH-10 แผนผังโรงงาน | รูปแผนผัง (Layout) ของแต่ละโรงงานพร้อมจุดตำแหน่งเครื่อง สีตามสถานะ เครื่องหยุดเสียมีวงกระพริบและป้ายรหัส กดที่จุดเพื่อเปิดเครื่อง แอดมินอัปโหลดรูปและจัดตำแหน่งได้ โรงงานที่ยังไม่มีรูปแสดงเป็นผังโซนตามกระบวนการ |
| SH-00 แจ้งซ่อมด่วน | สำหรับฝ่ายผลิตบนมือถือ: เลือกเครื่อง → แตะอาการ → บอกว่าเครื่องหยุดหรือไม่ แนบรูปจากกล้องได้ ผู้ใช้ role operator จะเข้าหน้านี้เป็นหน้าแรก |
| SH-02 งานซ่อม | ตารางใบงานเต็มความกว้าง: ชิปสถานะ ความสำคัญ ผู้รับผิดชอบ วันที่แจ้ง ค้นหาและกรองตามสถานะได้ กดลูกศรเพื่อดูรายละเอียดในแถว แบ่งหน้าละ 15 รายการ สลับเป็นมุมมองแยกกลุ่ม รออนุมัติ / กำลังดำเนินการ / ปิดแล้ว (เพิ่มงานในแถวได้ทันที) กดชื่องานเพื่อเปิดรายละเอียดด้านขวา แจ้งซ่อม → อนุมัติ → ซ่อม/รออะไหล่ → ปิดงาน ปิดงานต้องมีรหัสสาเหตุและการแก้ไขที่ต้นเหตุ เบิกอะไหล่เข้าใบงาน (ตัดสต็อกให้) ทุกการเปลี่ยนแปลงลงบันทึก REV ส่งออก CSV ได้ |
| SH-03 เครื่องจักร | ทะเบียนเครื่อง ค้นหาและกรองตามตำแหน่ง/สถานะการใช้งาน แบ่งหน้า หมวดเครื่อง สถานะการใช้งาน (In Use / Standby / Unused / Cancelled) ระดับ A/B/C เวลาหยุด 7 วัน แผน PM ประวัติงาน และใบตรวจ TPM ตามเลขที่ WI ของเครื่อง |
| SH-04 แผน PM | PM compliance 30 วัน กราฟแผนเทียบทำจริงรายเดือนทั้งปี สรุปตามกำหนดและตามรอบความถี่ มุมมองรายการ (เลยกำหนด / ภายใน 7 วัน / ถัดไป) และปฏิทินรายเดือน บันทึกว่าทำแล้วจะเลื่อนรอบถัดไปและสร้างใบงาน PM ให้ |
| SH-05 อะไหล่ | คงเหลือพร้อมหน่วยนับเทียบ Min/Max สถานะ (ปกติ / ถึงจุดสั่งซื้อ / หมดสต็อก) จำนวนที่ควรสั่ง รับเข้าและเบิกออกพร้อมเลขที่อ้างอิง ประวัติการเคลื่อนไหวสต็อก ส่งออกรายการสั่งซื้อเป็น CSV |
| SH-06 เครื่องมือวัด | ทะเบียนและรอบสอบเทียบตาม ISO 9001 ข้อ 7.1.5 บันทึกผ่าน/ไม่ผ่าน เครื่องมือที่ไม่ผ่านเป็น "ห้ามใช้" |
| SH-07 รายงาน KPI | ช่วง 7/30/90 วัน: Availability, MTBF, MTTR, PM compliance, เวลาหยุดรายเครื่อง และ Pareto สาเหตุการเสีย ส่งออก CSV |
| SH-08 ตั้งค่า | เพิ่มผู้ใช้ รีเซ็ตรหัสผ่าน เปลี่ยนรหัสผ่านตัวเอง นำเข้า CSV ใส่ข้อมูลตัวอย่าง และดาวน์โหลดไฟล์สำรอง JSON |

## ตั้งค่าเพื่อใช้งานจริงในบริษัท (ทำครั้งเดียว ประมาณ 15 นาที)

ระบบใช้ Firebase ของ Google เป็นฐานข้อมูลและระบบล็อกอิน แพ็กเกจฟรี (Spark) พอสำหรับทีมซ่อมบำรุงขนาดเล็กถึงกลาง ไม่ต้องผูกบัตร

### 1. สร้างโปรเจกต์
1. เข้า https://console.firebase.google.com ด้วยบัญชี Google ของบริษัท (แนะนำบัญชีกลาง ไม่ใช่บัญชีส่วนตัว)
2. กด "Create a project" ตั้งชื่อ เช่น `cmms-โรงงาน` ปิด Google Analytics ได้

### 2. เปิดระบบล็อกอิน
1. เมนู Build › Authentication › Get started
2. แท็บ Sign-in method › Email/Password › เปิด (Enable) แล้ว Save
   พนักงานล็อกอินด้วย **รหัสพนักงาน + รหัสผ่าน** ไม่ต้องมีอีเมล ระบบสร้างอีเมลเบื้องหลังที่ไม่มีใครใช้จริง (`…@cmms.example.com`) ให้ Firebase เอง จึงยังต้องเปิด Email/Password
3. แท็บ Settings › User actions › ต้องเปิด "Enable create (sign-up)" ไว้ ระบบใช้สร้างบัญชีให้พนักงานจากหน้าตั้งค่า บัญชีที่สมัครเองโดยไม่มีแอดมินเพิ่มจะเข้าดูข้อมูลไม่ได้ เพราะกฎใน `firestore.rules` บังคับไว้
4. แท็บ Settings › Authorized domains › Add domain › ใส่ `jittrakan-k.github.io`

### 3. สร้างฐานข้อมูล
1. เมนู Build › Firestore Database › Create database
2. เลือก location `asia-southeast1 (Singapore)` หรือที่ใกล้โรงงานที่สุด **เปลี่ยนภายหลังไม่ได้**
3. เลือก "Start in production mode"
4. แท็บ Rules › ลบข้อความเดิมทั้งหมด › วางเนื้อหาไฟล์ `firestore.rules` ทั้งไฟล์ › Publish
5. ทุกครั้งที่ไฟล์ `firestore.rules` ใน repository นี้เปลี่ยน ต้องวางใหม่และ Publish อีกครั้ง หรือตั้งค่าให้เผยแพร่อัตโนมัติตามหัวข้อ "เผยแพร่ firestore.rules อัตโนมัติ"

### 4. เชื่อมเว็บกับโปรเจกต์
1. หน้า Project Overview › กดไอคอน `</>` (Web) › ตั้งชื่อแอป › Register app (ไม่ต้องเลือก Hosting)
2. คัดลอกค่า `firebaseConfig` ที่แสดง
3. วางค่าใน `js/firebase-config.js` แทน `null` แล้ว commit ขึ้น `main` ทุกเครื่องจะเชื่อมโปรเจกต์เดียวกันเอง ค่าชุดนี้ไม่ใช่รหัสลับ สิ่งที่กันข้อมูลคือกฎความปลอดภัย

### 5. ตั้งค่าครั้งแรกในเว็บ
1. เปิด `https://jittrakan-k.github.io/cmms/` จะขึ้นหน้า "ตั้งค่าครั้งแรก"
2. ใส่ชื่อโรงงาน แผนก ชื่อ รหัสพนักงาน และรหัสผ่าน บัญชีนี้จะเป็นแอดมินคนแรก หน้านี้จะปิดถาวรหลังกดสร้าง
3. หน้าตั้งค่า › เพิ่มผู้ใช้ ใส่ชื่อ รหัสพนักงาน และสิทธิ์ ระบบจะแสดงรหัสผ่านชั่วคราว 8 ตัวครั้งเดียว ให้แจ้งพนักงาน พนักงานเข้าครั้งแรกต้องตั้งรหัสผ่านของตัวเอง
4. นำเข้าเครื่องจักรและอะไหล่จาก Excel (บันทึกเป็น CSV UTF-8 ตามไฟล์ตัวอย่าง) หรือกดใส่ข้อมูลตัวอย่างเพื่อทดลองก่อน

| ASST. Manager | แอดมิน (`admin`) | อนุมัติใบงาน เพิ่มและเปลี่ยนตำแหน่งผู้ใช้ นำเข้าข้อมูล เพิ่ม แก้ไข ลบ เครื่อง แผน PM อะไหล่ เครื่องมือวัด |
| Advisor | แอดมิน (`admin`) | เหมือน ASST. Manager |
| Admin Website | แอดมิน (`admin`) | ผู้ดูแลเว็บ สิทธิ์เหมือน ASST. Manager และลบบัญชีผู้ใช้คนอื่นได้ (ลบบัญชีตัวเองไม่ได้) |
| Machine | ช่างซ่อมบำรุง (`tech`) | รับงานที่อนุมัติแล้ว ซ่อม ปิดงาน เบิกอะไหล่เข้าใบงาน ทำ PM รับอะไหล่ บันทึกผลสอบเทียบ |
| Design | ช่างซ่อมบำรุง (`tech`) | เหมือน Machine |

| Document | ฝ่ายผลิต (`operator`) | แจ้งซ่อมและดูข้อมูล เปิดเว็บจะเข้าหน้าแจ้งซ่อมด่วนทันที |

แอดมินลดสิทธิ์หรือลบบัญชีตัวเองไม่ได้ เพื่อไม่ให้ระบบไม่มีแอดมินเหลือ ถ้าต้องเปลี่ยนแอดมิน ให้เพิ่มแอดมินคนใหม่ก่อนแล้วให้คนใหม่ปรับสิทธิ์คนเดิม

รหัสพนักงานใช้ได้ A-Z 0-9 . _ - ยาว 2–20 ตัว พิมพ์เล็กหรือใหญ่ก็ได้ เปลี่ยนภายหลังไม่ได้

เปลี่ยนรหัสผ่านเอง: หน้าตั้งค่า › บัญชีของฉัน

ลืมรหัสผ่าน: แอดมินกด "รีเซ็ตรหัสผ่าน" ที่แถวของพนักงานในหน้าตั้งค่า ระบบให้รหัสชั่วคราวใหม่ และบัญชีเดิมใช้ไม่ได้ทันที (เบื้องหลังคือสร้างบัญชีล็อกอินใหม่ให้รหัสพนักงานเดิม จึงเห็นบัญชีเก่าค้างใน Firebase console › Authentication ลบทิ้งได้ถ้าต้องการ) ถ้าแอดมินคนเดียวลืมรหัสผ่านเอง ให้เพิ่มแอดมินสำรองไว้อีกคนตั้งแต่แรก

## เผยแพร่ firestore.rules อัตโนมัติ
`.github/workflows/deploy-rules.yml` เผยแพร่กฎขึ้น Firebase ทุกครั้งที่ `firestore.rules` บน `main` เปลี่ยน (หรือกด Run workflow เองที่แท็บ Actions) ถ้ากฎเขียนผิด Firebase จะไม่รับและ workflow แสดงเป็นสีแดง กฎเดิมยังใช้ต่อ

ใช้ Workload Identity Federation: GitHub ยืนยันตัวกับ Google โดยตรง ไม่มีไฟล์กุญแจ จึงใช้ได้แม้บริษัทปิดการสร้าง service account key และอนุญาตเฉพาะ repository `Jittrakan-K/cmms` service account มีแค่ role Firebase Rules Admin (แก้กฎได้อย่างเดียว อ่านหรือแก้ข้อมูลไม่ได้)

ตั้งค่าครั้งเดียว: เปิด https://console.cloud.google.com/?project=cmmsepic กดไอคอน Cloud Shell (>_) มุมขวาบน แล้ววางคำสั่งนี้ทั้งชุด

```bash
PROJECT=cmmsepic; REPO=Jittrakan-K/cmms; SA=github-rules-deploy@$PROJECT.iam.gserviceaccount.com
gcloud config set project $PROJECT
gcloud services enable iamcredentials.googleapis.com sts.googleapis.com firebaserules.googleapis.com
gcloud iam service-accounts describe $SA >/dev/null 2>&1 || gcloud iam service-accounts create github-rules-deploy --display-name="GitHub rules deploy"
gcloud projects add-iam-policy-binding $PROJECT --member="serviceAccount:$SA" --role="roles/firebaserules.admin" --condition=None
gcloud iam workload-identity-pools describe github --location=global >/dev/null 2>&1 || gcloud iam workload-identity-pools create github --location=global --display-name="GitHub"
gcloud iam workload-identity-pools providers describe cmms --location=global --workload-identity-pool=github >/dev/null 2>&1 || gcloud iam workload-identity-pools providers create-oidc cmms --location=global --workload-identity-pool=github --display-name="cmms repo" --issuer-uri="https://token.actions.githubusercontent.com" --attribute-mapping="google.subject=assertion.sub,attribute.repository=assertion.repository" --attribute-condition="assertion.repository=='$REPO'"
PN=$(gcloud projects describe $PROJECT --format='value(projectNumber)')
gcloud iam service-accounts add-iam-policy-binding $SA --role=roles/iam.workloadIdentityUser --member="principalSet://iam.googleapis.com/projects/$PN/locations/global/workloadIdentityPools/github/attribute.repository/$REPO"
echo "เสร็จแล้ว project number = $PN"
```

ถ้าบรรทัดสุดท้ายแสดง project number ไม่ใช่ `607234875826` ให้แก้ค่า `WIF_PROVIDER` ใน workflow ให้ตรง จากนั้นแท็บ Actions › Deploy Firestore rules › Run workflow เพื่อเผยแพร่ครั้งแรก

## ข้อจำกัด

- แจ้งซ่อม ทำ PM และเบิกอะไหล่ใช้ transaction จึงต้องออนไลน์ ส่วนการดูข้อมูลล่าสุดใช้แคชในเครื่องได้เมื่อสัญญาณหลุด
- หน้าใบสั่งงานโหลดล่าสุด 2,000 ใบ (รวมใบงานย้อนหลัง) เพื่อคุมโควตาการอ่าน
- `firestore.rules` ยังไม่ได้ทดสอบกับเซิร์ฟเวอร์จริง หลัง Publish ให้ลองตั้งค่าครั้งแรก เพิ่มผู้ใช้แต่ละสิทธิ์ แล้วล็อกอินทดสอบก่อนให้ทุกคนใช้

## นำเข้าใบตรวจ TPM
ไฟล์ CSV หนึ่งแถวต่อหนึ่งจุดตรวจ หัวตาราง `wi, machine_type, kind, part, check, freq_days, standard` (ความถี่เป็นจำนวนวัน) ระบบรวมเป็นใบตามเลขที่ WI และผูกกับเครื่องที่มีช่อง `wi` ตรงกัน ผลตรวจเก็บใน `inspections` และวันที่ตรวจล่าสุดของแต่ละจุดใน `tpmState/{รหัสเครื่อง}` ต้องเผยแพร่ `firestore.rules` ชุดล่าสุดก่อนใช้งาน

## นำเข้าใบงานย้อนหลังจาก Job Request list
หน้าตั้งค่า › นำเข้าใบงานย้อนหลัง (Job Request) ใช้ไฟล์ CSV หัวตาราง `ref, section, request_date, complete_date, condition, type, status, machine_code, machine_name, process, detail, action, action_by, cost, note` (วันที่เป็น ปปปป-ดด-วว)
- เลขที่ Request (เช่น FR-M26-001) ใช้เป็นเลขที่ใบงาน นำเข้าซ้ำจะข้ามใบที่มีอยู่แล้ว
- ถ้ามีคอลัมน์ `start_time, end_time` (ชช:นน) ใบนั้นใช้เวลาจริงและนับใน MTTR / เวลาหยุด เช่น รายงานการเข้าซ่อมบำรุง; คอลัมน์ `team` (คั่นด้วย ;) และ `priority` (Urgent/High/Normal/Easy) ใส่เพิ่มได้
- ใบงานย้อนหลังที่มีแต่วันที่ ไม่มีเวลาหยุดเครื่องจริง จึงนับเป็นจำนวนครั้งที่เสียและประวัติเครื่อง แต่ไม่นับใน Availability, MTTR, เวลาหยุดรวม และ PM compliance
- เครื่องที่ไม่อยู่ในทะเบียนปัจจุบัน (เลิกใช้แล้ว) ยังนำเข้าได้ ใบงานแสดงรหัสและชื่อเครื่องตามไฟล์
- ต้องเผยแพร่ `firestore.rules` ชุดล่าสุดก่อนนำเข้า

ไฟล์นำเข้าเครื่องจักรรองรับช่องเพิ่มเติม `serial, asset_no, installed, area, owner, doc_url` ช่องที่ว่างในไฟล์จะไม่เขียนทับข้อมูลเดิม จึงนำเข้าซ้ำเพื่อเติมข้อมูลได้ หน้าเครื่องแสดง Serial No., Asset No., วันที่ติดตั้ง, กระบวนการ, ผู้รับผิดชอบ และลิงก์เปิดเอกสาร WI

## นำเข้าแผน PM
หน้าตั้งค่า › นำเข้าแผน PM ใช้ไฟล์ CSV หัวตาราง `id, asset, task, interval_days, due_date, source` หนึ่งแถวต่อหนึ่งแผนของหนึ่งเครื่อง (`due_date` คือวันครบกำหนดครั้งถัดไป ปปปป-ดด-วว) นำเข้าซ้ำจะข้ามแผนที่มีอยู่แล้ว เพื่อไม่ทับวันครบกำหนดที่เลื่อนไปหลังทำ PM

## ราคาอะไหล่
ไฟล์นำเข้าอะไหล่มีคอลัมน์ `price` (บาทต่อหน่วย) หน้าคลังอะไหล่แสดงราคา และใบงานแสดงมูลค่าอะไหล่ที่เบิก อะไหล่ที่ยังไม่ตั้ง Min/Max และไม่มีของ (รายการจากรหัสอะไหล่หรือใบสั่งซื้อ) แสดงเป็น "ยังไม่ตั้งจุดสั่งซื้อ" ไม่นับเป็นอะไหล่หมด ช่องที่ว่างในไฟล์จะไม่ทับค่าเดิมของอะไหล่ที่มีอยู่แล้ว

## ยกเลิกใบงาน
ใช้เมื่อสร้างใบงานผิดหรือซ้ำ ในหน้างานซ่อมกดลูกศรหน้าแถวแล้วกด "ยกเลิกใบงาน" หรือเปิดใบงานแล้วกด "ยกเลิกใบงานนี้" ใต้ปุ่มอนุมัติ ต้องใส่เหตุผลก่อนยืนยัน
- แอดมินยกเลิกได้ทุกใบที่ยังไม่ปิด ผู้แจ้งยกเลิกใบของตัวเองได้ระหว่างรออนุมัติ ช่างยกเลิกไม่ได้
- อะไหล่ที่เบิกเข้าใบงานจะคืนเข้าคลังให้อัตโนมัติ และลงประวัติรับเข้าพร้อมเลขที่ใบงาน
- หน้างานซ่อมซ่อนใบที่ยกเลิกไว้เป็นค่าเริ่มต้น กดปุ่ม "แสดงงานที่ยกเลิก" ข้างช่องค้นหาเพื่อแสดง (จำไว้ในเบราว์เซอร์เครื่องนั้น) หรือเลือกตัวกรองสถานะ "ยกเลิก"
- ใบงานที่ยกเลิกยังอยู่ในประวัติ แต่ไม่นับในสถิติ KPI ค่าใช้จ่าย และสถานะเครื่อง ยกเลิกแล้วแก้กลับไม่ได้
- ต้องเผยแพร่ `firestore.rules` ชุดล่าสุดก่อนใช้งาน ใบงานที่สร้างก่อนอัปเดตนี้ยกเลิกได้เฉพาะแอดมิน

## ค่าใช้จ่ายซ่อมบำรุง
ทุกใบงานมีส่วน "ค่าใช้จ่าย" (เลขที่ PR ค่าใช้จ่ายเป็นบาท และรายละเอียด) ช่างบันทึกได้ระหว่างงาน แอดมินแก้ได้ทุกเวลา หน้ารายงาน KPI มีกราฟค่าใช้จ่ายรายเดือนแยก PM (นับตามวันที่ปิดงาน) กับงานซ่อม (นับตามวันที่เปิดใบงาน)

## หน้าโหลด
ตอนเปิดเว็บและหลังเข้าสู่ระบบจะแสดงโลโก้น็อตหกเหลี่ยมหมุนทีละ 60 องศา พร้อมข้อความต้อนรับ จนข้อมูลเครื่องจักรและใบงานชุดแรกโหลดเสร็จ (แสดงอย่างน้อย 0.9 วินาที และไม่เกิน 10 วินาที) ถ้าเครื่องตั้งค่าลดการเคลื่อนไหวไว้ โลโก้จะไม่หมุน

## หนึ่งหน้าจอต่อหน้า
บนจอคอมพิวเตอร์และแท็บเล็ตแนวนอน แต่ละหน้าจัดให้พอดีหนึ่งจอโดยไม่ต้องเลื่อนลง ส่วนที่เกินจะแบ่งเป็นหน้าถัดไป เปลี่ยนหน้าด้วยปุ่ม "ก่อนหน้า / ถัดไป" จุดบอกหน้า (หรือช่องเลือกหน้าเมื่อมีมากกว่า 12 หน้า) หรือคีย์ PageUp / PageDown / ลูกศรซ้ายขวา ตารางยาวจะแบ่งแถวต่อหน้าถัดไปโดยหัวตารางแสดงทุกหน้า บนโทรศัพท์ยังเลื่อนลงตามปกติ ปิดได้ที่หน้าตั้งค่า > การแสดงผล (จำไว้ในเบราว์เซอร์เครื่องนั้น)

## แดชบอร์ดเมื่อมีเครื่องจำนวนมาก
เมื่อมีเครื่องเกิน 48 เครื่องหรือมีรูปแผนผังแล้ว แดชบอร์ดแสดงแผนผังทีละโรงงาน (เลือกโรงงานจากแถบด้านบน) เครื่องที่หยุด รออะไหล่ ทำ PM หรือ PM เลยกำหนดแสดงเป็นการ์ดใต้แผนผัง กด "แสดงทุกเครื่องเป็นการ์ด" เพื่อดูทั้งหมด

## แผนผังโรงงาน
แผนผังแต่ละรูปคือหนึ่งอาคารหรือหนึ่งพื้นที่ (เช่น Fac A, Fac B) ไม่ผูกกับไลน์ เครื่องจากหลายไลน์อยู่บนแผนผังเดียวกันได้
1. หน้าแผนผังโรงงาน กด "เพิ่มแผนผัง" (แอดมิน) ตั้งชื่อ แล้วเลือกรูป JPG, PNG, WebP หรือ PDF (ใช้หน้าแรก) ระบบย่อเป็นภาพ WebP ไม่เกินประมาณ 1 MB แล้วเก็บใน Firestore คอลเลกชัน `maps` ไม่ต้องเปิด Firebase Storage
2. เลือกแผนผังจากแถบด้านบน กด "จัดตำแหน่งเครื่อง" เลือกเครื่องจากรายการทางขวา (กรองตามไลน์หรือค้นหาได้) แล้วคลิกบนแผนผังตรงตำแหน่งเครื่อง ระบบจะเลือกเครื่องถัดไปที่ยังไม่ได้วางให้ ลากจุดเพื่อย้าย หรือกด "เอา ... ออกจากแผนผัง"
3. เครื่องเก็บ `mapId` กับตำแหน่งเป็นสัดส่วนของรูป (`mapX`, `mapY` 0–1) "เปลี่ยนรูป" ที่สัดส่วนเดิมจะใช้ตำแหน่งเดิมได้
4. แท็บ "ยังไม่ได้วางบนแผนผัง" แสดงเครื่องที่เหลือเป็นผังโซนตามไลน์และกระบวนการ
5. วางทีละมากๆ: กด "ส่งออกตำแหน่ง CSV" ได้ไฟล์ `id, name, line, map, map_x, map_y` (`map` คือชื่อแผนผัง, ตำแหน่งเป็นเปอร์เซ็นต์ 0–100 จากมุมซ้ายบน) แก้ใน Excel แล้วนำเข้าที่หน้าตั้งค่า › นำเข้าเครื่องจักร ช่องที่ว่างไม่ทับตำแหน่งเดิม
