# CMMS

ระบบบริหารงานซ่อมบำรุง เว็บ HTML5 ล้วน ไม่ต้อง build

เปิดครั้งแรกจะใช้ข้อมูลตัวอย่าง (ไลน์ SMT 2 ไลน์) ที่เก็บในเบราว์เซอร์เครื่องนั้น จนกว่าจะเชื่อม Firebase

## หน้าในระบบ

| แผ่นงาน | หน้าที่ |
| --- | --- |
| SH-09 แดชบอร์ด | หน้าแรกหลังเข้าสู่ระบบ การ์ดตัวเลขสรุป 5 ใบ (เครื่องจักร ใบงานที่ยังไม่ปิด กำลังซ่อม ปิดงานเดือนนี้ PM ภายใน 7 วัน) กราฟใบแจ้งซ่อมรายเดือนคู่เส้น PM ที่ทำเสร็จ โดนัทสถานะใบงานและสุขภาพเครื่องจักร แผนผังเครื่องจักรแยกตามไลน์ ใบงานล่าสุด PM ที่จะถึง คลังอะไหล่ หมวดเครื่อง ทีมช่าง และเครื่องมือวัด มีโหมดจอทีวี (เปลี่ยนหน้าเองทุก 20 วินาที) อัปเดตเองเมื่อข้อมูลเปลี่ยน |
| SH-01 ภาพรวม | เครื่องที่หยุดอยู่, Availability, MTBF, MTTR, แผนภูมิสถานะ 7 วัน, งานค้าง, PM ครบกำหนด, อะไหล่ถึงจุดสั่งซื้อ, เครื่องมือวัดที่ต้องดู |
| SH-00 แจ้งซ่อมด่วน | สำหรับฝ่ายผลิตบนมือถือ: เลือกเครื่อง → แตะอาการ → บอกว่าเครื่องหยุดหรือไม่ แนบรูปจากกล้องได้ ผู้ใช้ role operator จะเข้าหน้านี้เป็นหน้าแรก |
| SH-02 งานซ่อม | ตารางใบงานเต็มความกว้าง: ชิปสถานะ ความสำคัญ ผู้รับผิดชอบ วันที่แจ้ง ค้นหาและกรองตามสถานะได้ กดลูกศรเพื่อดูรายละเอียดในแถว แบ่งหน้าละ 15 รายการ สลับเป็นมุมมองแยกกลุ่ม รออนุมัติ / กำลังดำเนินการ / ปิดแล้ว (เพิ่มงานในแถวได้ทันที) กดชื่องานเพื่อเปิดรายละเอียดด้านขวา แจ้งซ่อม → อนุมัติ → ซ่อม/รออะไหล่ → ปิดงาน ปิดงานต้องมีรหัสสาเหตุและการแก้ไขที่ต้นเหตุ เบิกอะไหล่เข้าใบงาน (ตัดสต็อกให้) ทุกการเปลี่ยนแปลงลงบันทึก REV ส่งออก CSV ได้ |
| SH-03 เครื่องจักร | ทะเบียนเครื่อง ค้นหาและกรองตามตำแหน่ง/สถานะการใช้งาน แบ่งหน้า หมวดเครื่อง สถานะการใช้งาน (In Use / Standby / Unused / Cancelled) ระดับ A/B/C เวลาหยุด 7 วัน แผน PM ประวัติงาน และใบตรวจ TPM ตามเลขที่ WI ของเครื่อง |
| SH-04 แผน PM | PM compliance 30 วัน กราฟแผนเทียบทำจริงรายเดือนทั้งปี สรุปตามกำหนดและตามรอบความถี่ มุมมองรายการ (เลยกำหนด / ภายใน 7 วัน / ถัดไป) และปฏิทินรายเดือน บันทึกว่าทำแล้วจะเลื่อนรอบถัดไปและสร้างใบงาน PM ให้ |
| SH-05 อะไหล่ | คงเหลือพร้อมหน่วยนับเทียบ Min/Max สถานะ (ปกติ / ถึงจุดสั่งซื้อ / หมดสต็อก) จำนวนที่ควรสั่ง รับเข้าและเบิกออกพร้อมเลขที่อ้างอิง ประวัติการเคลื่อนไหวสต็อก ส่งออกรายการสั่งซื้อเป็น CSV |
| SH-06 เครื่องมือวัด | ทะเบียนและรอบสอบเทียบตาม ISO 9001 ข้อ 7.1.5 บันทึกผ่าน/ไม่ผ่าน เครื่องมือที่ไม่ผ่านเป็น "ห้ามใช้" |
| SH-07 รายงาน KPI | ช่วง 7/30/90 วัน: Availability, MTBF, MTTR, PM compliance, เวลาหยุดรายเครื่อง และ Pareto สาเหตุการเสีย ส่งออก CSV |
| SH-08 ตั้งค่า | เพิ่มผู้ใช้ รีเซ็ตรหัสผ่าน เปลี่ยนรหัสผ่านตัวเอง นำเข้า CSV ใส่ข้อมูลตัวอย่าง และดาวน์โหลดไฟล์สำรอง JSON |

ช่องค้นหาด้านบนค้นได้ทั้งใบงาน เครื่องจักร อะไหล่ และเครื่องมือวัด

PM compliance = PM ที่ทำทันวันครบกำหนดในช่วงเวลา ÷ (PM ที่ทำในช่วงเวลา + PM ที่เลยกำหนดค้างอยู่)

## ตั้งค่าเพื่อใช้งานจริงในบริษัท (ทำครั้งเดียว ประมาณ 15 นาที)

ระบบใช้ Firebase ของ Google เป็นฐานข้อมูลและระบบล็อกอิน แพ็กเกจฟรี (Spark) พอสำหรับทีมซ่อมบำรุงขนาดเล็กถึงกลาง ไม่ต้องผูกบัตร

### 1. สร้างโปรเจกต์
1. เข้า https://console.firebase.google.com ด้วยบัญชี Google ของบริษัท (แนะนำบัญชีกลาง ไม่ใช่บัญชีส่วนตัว)
2. กด "Create a project" ตั้งชื่อ เช่น `cmms-โรงงาน` ปิด Google Analytics ได้

### 2. เปิดระบบล็อกอิน
1. เมนู Build › Authentication › Get started
2. แท็บ Sign-in method › Email/Password › เปิด (Enable) แล้ว Save
   พนักงานล็อกอินด้วย **รหัสพนักงาน + รหัสผ่าน** ไม่ต้องมีอีเมล ระบบสร้างอีเมลเบื้องหลังที่ไม่มีใครใช้จริง (`…@cmms.example.com`) ให้ Firebase เอง จึงยังต้องเปิด Email/Password
3. แท็บ Settings › User actions › ต้องเปิด "Enable create (sign-up)" ไว้ ระบบใช้สร้างบัญชีให้พนักงานจากหน้าตั้งค่า บัญชีที่สมัครเองโดยไม่มีแอดมินเพิ่มจะเข้าดูข้อมูลไม่ได้ เพราะกฎใน `firestore.rules` บังคับไว้
4. แท็บ Settings › Authorized domains › Add domain › ใส่ `jittrakan-k.github.io`

### 3. สร้างฐานข้อมูล
1. เมนู Build › Firestore Database › Create database
2. เลือก location `asia-southeast1 (Singapore)` หรือที่ใกล้โรงงานที่สุด **เปลี่ยนภายหลังไม่ได้**
3. เลือก "Start in production mode"
4. แท็บ Rules › ลบข้อความเดิมทั้งหมด › วางเนื้อหาไฟล์ `firestore.rules` ทั้งไฟล์ › Publish
5. ทุกครั้งที่ไฟล์ `firestore.rules` ใน repository นี้เปลี่ยน ต้องวางใหม่และ Publish อีกครั้ง

### 4. เชื่อมเว็บกับโปรเจกต์
1. หน้า Project Overview › กดไอคอน `</>` (Web) › ตั้งชื่อแอป › Register app (ไม่ต้องเลือก Hosting)
2. คัดลอกค่า `firebaseConfig` ที่แสดง
3. วางค่าใน `js/firebase-config.js` แทน `null` แล้ว commit ขึ้น `main` ทุกเครื่องจะเชื่อมโปรเจกต์เดียวกันเอง ค่าชุดนี้ไม่ใช่รหัสลับ สิ่งที่กันข้อมูลคือกฎความปลอดภัย

### 5. ตั้งค่าครั้งแรกในเว็บ
1. เปิด `https://jittrakan-k.github.io/cmms/` จะขึ้นหน้า "ตั้งค่าครั้งแรก"
2. ใส่ชื่อโรงงาน แผนก ชื่อ รหัสพนักงาน และรหัสผ่าน บัญชีนี้จะเป็นแอดมินคนแรก หน้านี้จะปิดถาวรหลังกดสร้าง
3. หน้าตั้งค่า › เพิ่มผู้ใช้ ใส่ชื่อ รหัสพนักงาน และสิทธิ์ ระบบจะแสดงรหัสผ่านชั่วคราว 8 ตัวครั้งเดียว ให้แจ้งพนักงาน พนักงานเข้าครั้งแรกต้องตั้งรหัสผ่านของตัวเอง
4. นำเข้าเครื่องจักรและอะไหล่จาก Excel (บันทึกเป็น CSV UTF-8 ตามไฟล์ตัวอย่าง) หรือกดใส่ข้อมูลตัวอย่างเพื่อทดลองก่อน

## ตำแหน่งและสิทธิ์ผู้ใช้

ตอนเพิ่มผู้ใช้ให้เลือกตำแหน่ง ระบบจะกำหนดสิทธิ์ตามตำแหน่งให้เอง

| ตำแหน่ง | สิทธิ์ในระบบ | ทำอะไรได้ |
| --- | --- | --- |
| ASST. Manager | แอดมิน (`admin`) | อนุมัติใบงาน เพิ่มและเปลี่ยนตำแหน่งผู้ใช้ นำเข้าข้อมูล เพิ่ม แก้ไข ลบ เครื่อง แผน PM อะไหล่ เครื่องมือวัด |
| Advisor | แอดมิน (`admin`) | เหมือน ASST. Manager |
| Admin Website | แอดมิน (`admin`) | ผู้ดูแลเว็บ สิทธิ์เหมือน ASST. Manager และลบบัญชีผู้ใช้คนอื่นได้ (ลบบัญชีตัวเองไม่ได้) |
| Machine | ช่างซ่อมบำรุง (`tech`) | รับงานที่อนุมัติแล้ว ซ่อม ปิดงาน เบิกอะไหล่เข้าใบงาน ทำ PM รับอะไหล่ บันทึกผลสอบเทียบ |
| Design | ช่างซ่อมบำรุง (`tech`) | เหมือน Machine |
| Document | ฝ่ายผลิต (`operator`) | แจ้งซ่อมและดูข้อมูล เปิดเว็บจะเข้าหน้าแจ้งซ่อมด่วนทันที |
| ปิดใช้งาน | `disabled` | ล็อกอินได้แต่เห็นข้อมูลไม่ได้ ใช้เมื่อพนักงานลาออก |

แอดมินลดสิทธิ์หรือลบบัญชีตัวเองไม่ได้ เพื่อไม่ให้ระบบไม่มีแอดมินเหลือ ถ้าต้องเปลี่ยนแอดมิน ให้เพิ่มแอดมินคนใหม่ก่อนแล้วให้คนใหม่ปรับสิทธิ์คนเดิม

รหัสพนักงานใช้ได้ A-Z 0-9 . _ - ยาว 2–20 ตัว พิมพ์เล็กหรือใหญ่ก็ได้ เปลี่ยนภายหลังไม่ได้

เปลี่ยนรหัสผ่านเอง: หน้าตั้งค่า › บัญชีของฉัน

ลืมรหัสผ่าน: แอดมินกด "รีเซ็ตรหัสผ่าน" ที่แถวของพนักงานในหน้าตั้งค่า ระบบให้รหัสชั่วคราวใหม่ และบัญชีเดิมใช้ไม่ได้ทันที (เบื้องหลังคือสร้างบัญชีล็อกอินใหม่ให้รหัสพนักงานเดิม จึงเห็นบัญชีเก่าค้างใน Firebase console › Authentication ลบทิ้งได้ถ้าต้องการ) ถ้าแอดมินคนเดียวลืมรหัสผ่านเอง ให้เพิ่มแอดมินสำรองไว้อีกคนตั้งแต่แรก

## ข้อจำกัด

- แจ้งซ่อม ทำ PM และเบิกอะไหล่ใช้ transaction จึงต้องออนไลน์ ส่วนการดูข้อมูลล่าสุดใช้แคชในเครื่องได้เมื่อสัญญาณหลุด
- หน้าใบสั่งงานโหลดล่าสุด 300 ใบเพื่อคุมโควตาการอ่าน
- `firestore.rules` ยังไม่ได้ทดสอบกับเซิร์ฟเวอร์จริง หลัง Publish ให้ลองตั้งค่าครั้งแรก เพิ่มผู้ใช้แต่ละสิทธิ์ แล้วล็อกอินทดสอบก่อนให้ทุกคนใช้

## นำเข้าใบตรวจ TPM
ไฟล์ CSV หนึ่งแถวต่อหนึ่งจุดตรวจ หัวตาราง `wi, machine_type, kind, part, check, freq_days, standard` (ความถี่เป็นจำนวนวัน) ระบบรวมเป็นใบตามเลขที่ WI และผูกกับเครื่องที่มีช่อง `wi` ตรงกัน ผลตรวจเก็บใน `inspections` และวันที่ตรวจล่าสุดของแต่ละจุดใน `tpmState/{รหัสเครื่อง}` ต้องเผยแพร่ `firestore.rules` ชุดล่าสุดก่อนใช้งาน

## ยกเลิกใบงาน
ใช้เมื่อสร้างใบงานผิดหรือซ้ำ เปิดใบงาน แล้วกด "ยกเลิกใบงานนี้" ในกล่องด้านขวา ต้องใส่เหตุผลก่อนยืนยัน
- แอดมินยกเลิกได้ทุกใบที่ยังไม่ปิด ผู้แจ้งยกเลิกใบของตัวเองได้ระหว่างรออนุมัติ ช่างยกเลิกไม่ได้
- อะไหล่ที่เบิกเข้าใบงานจะคืนเข้าคลังให้อัตโนมัติ และลงประวัติรับเข้าพร้อมเลขที่ใบงาน
- ใบงานที่ยกเลิกยังอยู่ในประวัติ (กรองสถานะ "ยกเลิก" ได้) แต่ไม่นับในสถิติ KPI ค่าใช้จ่าย และสถานะเครื่อง ยกเลิกแล้วแก้กลับไม่ได้
- ต้องเผยแพร่ `firestore.rules` ชุดล่าสุดก่อนใช้งาน ใบงานที่สร้างก่อนอัปเดตนี้ยกเลิกได้เฉพาะแอดมิน

## ค่าใช้จ่ายซ่อมบำรุง
ทุกใบงานมีส่วน "ค่าใช้จ่าย" (เลขที่ PR ค่าใช้จ่ายเป็นบาท และรายละเอียด) ช่างบันทึกได้ระหว่างงาน แอดมินแก้ได้ทุกเวลา หน้ารายงาน KPI มีกราฟค่าใช้จ่ายรายเดือนแยก PM (นับตามวันที่ปิดงาน) กับงานซ่อม (นับตามวันที่เปิดใบงาน)

## หนึ่งหน้าจอต่อหน้า
บนจอคอมพิวเตอร์และแท็บเล็ตแนวนอน แต่ละหน้าจัดให้พอดีหนึ่งจอโดยไม่ต้องเลื่อนลง ส่วนที่เกินจะแบ่งเป็นหน้าถัดไป เปลี่ยนหน้าด้วยปุ่ม "ก่อนหน้า / ถัดไป" จุดบอกหน้า (หรือช่องเลือกหน้าเมื่อมีมากกว่า 12 หน้า) หรือคีย์ PageUp / PageDown / ลูกศรซ้ายขวา ตารางยาวจะแบ่งแถวต่อหน้าถัดไปโดยหัวตารางแสดงทุกหน้า บนโทรศัพท์ยังเลื่อนลงตามปกติ ปิดได้ที่หน้าตั้งค่า > การแสดงผล (จำไว้ในเบราว์เซอร์เครื่องนั้น)

## แดชบอร์ดเมื่อมีเครื่องจำนวนมาก
เมื่อมีเครื่องเกิน 48 เครื่อง แดชบอร์ดแสดงเฉพาะเครื่องที่หยุด รออะไหล่ ทำ PM หรือ PM เลยกำหนด ส่วนเครื่องที่ปกติสรุปเป็นจำนวนต่อไลน์ กด "แสดงทุกเครื่อง" เพื่อดูทั้งหมด
